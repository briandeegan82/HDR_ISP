# brilliantISP ↔ boltISP YAML Compatibility

This document defines the practical intersection between:

- `brilliantISP` YAMLs (full PyYAML + required top-level schema), and
- `boltISP` YAMLs (custom flat-indentation parser + selectively-consumed keys).

It covers both which config keys are shared and the algorithm-level differences
that have been harmonised (and those that remain).

---

## Key parser differences

- brilliantISP loads YAML with `yaml.safe_load` and validates many required
  sections.
- boltISP does not use a full YAML parser. It flattens `section.key` pairs and
  only reads known keys; unknown keys are silently ignored.
- For array-valued keys that boltISP consumes, **inline list form**
  (`[a, b, c]`) is the safest representation.

---

## Shared key intersection (safe to share)

The following keys are read by both systems with matching intent:

- `platform.filename`
- `sensor_info.width`, `sensor_info.height`, `sensor_info.bit_depth`
- `sensor_info.hdr_bit_depth`, `sensor_info.bayer_pattern`,
  `sensor_info.endian_type`, `sensor_info.data_format`
- `crop.*` core fields (`is_enable`, starts, size)
- `companding.is_enable`, `companding.pedestal`, `companding.companded_pin`,
  `companding.companded_pout`
- `dead_pixel_correction.is_enable`, `dead_pixel_correction.dp_threshold`
- `black_level_correction` offsets (`r_offset`, `gr_offset`, `gb_offset`,
  `b_offset`)
- `digital_gain` controls (`is_enable`, `is_auto`, `gain_array`,
  `current_gain`) and AGC fields if present
- `auto_white_balance.*`, `white_balance.*`
- `demosaic.algorithm`
- `color_correction_matrix.is_enable`, `corrected_red`, `corrected_green`,
  `corrected_blue`
- `gamma_correction.is_enable`, `gamma_correction.gamma`,
  `gamma_correction.curve`
- `hdr_durand.is_enable`, `sigma_space`, `sigma_color`, `contrast_factor`
- `color_saturation_enhancement.is_enable`, `saturation_gain`
- `ldci.is_enable`, `clip_limit`, `wind`
- `sharpen.is_enable`, `sharpen_sigma`, `sharpen_strength`

## Tone mapping selector

| brilliantISP key | boltISP key | Notes |
|-----------------|-------------|-------|
| `tone_mapping.tone_mapper` | `hdr_tone_mapping.operator` (falls back to `tone_mapping.operator`) | boltISP checks `hdr_tone_mapping.operator` first |

### Translation table

| brilliantISP `tone_mapper` | boltISP `operator` |
|----------------------------|--------------------|
| `durand`                   | `durand`           |
| `aces`                     | `aces`             |
| `hable`                    | `hable`            |
| `reinhard_integer`         | `reinhard`         |
| `aces_integer`             | `aces`             |
| `hable_integer`            | `hable`            |

### Recommended shared configuration (Hable float)

Both ISPs should use the **float Hable** operator with `tone_mapping_before_demosaic: false`:

```yaml
# brilliantISP
tone_mapping:
  tone_mapper: 'hable'
  tone_mapping_before_demosaic: false

hable:
  exposure_bias: 2.0    # must match boltISP hable_exposure_bias
  white_point: 11.2     # must match boltISP hable_white_point

# boltISP (hdr_tone_mapping section; generated by export_boltisp_yaml.py)
hdr_tone_mapping:
  operator: 'hable'
  hable_exposure_bias: 2.0
  hable_white_point: 11.2
  hable_hdr_scale: 1.0    # default; net pre-scale is 1×exposure_bias
```

**Important:** boltISP always applies tone mapping after CCM (post-demosaic).
brilliantISP previously applied it before demosaic
(`tone_mapping_before_demosaic: true`); setting this to `false` aligns both.

### `hdr_scale` / `hable_hdr_scale` semantics

- brilliantISP: `x * exposure_bias → hableCurve → / hableCurve(white_point)`
- boltISP: `x * hable_hdr_scale * exposure_bias → hableCurve → / hableCurve(white_point)`

With `hable_hdr_scale = 1.0` (default), both are equivalent for the same
`exposure_bias` and `white_point`.

## Lens shading correction (LSC)

boltISP reads **explicit gain grid tables** (`r_table`, `gr_table`, `gb_table`,
`b_table`) and **ignores `r_k1`, `r_k2`, etc.**

brilliantISP evaluates the radial polynomial `gain(r) = 1 + k1·r² + k2·r⁴`
at runtime.

### Generating boltISP grid tables from k1/k2

Use the export script (which now includes LSC table generation):

```bash
python tools/export_boltisp_yaml.py \
    --input  config/AD_cam.yml \
    --output /path/to/boltISP/config/AD_cam_from_brilliant.yml \
    --lsc-grid-width  17 \
    --lsc-grid-height 17
```

The script:
1. Reads `lens_shading_correction.{r,gr,gb,b}_k1` and `_k2` from the
   brilliantISP config.
2. Evaluates the polynomial on a uniform `grid_width × grid_height` grid
   (r=0 at image centre, r=1 at corners).
3. Writes `r_table`, `gr_table`, `gb_table`, `b_table` and
   `lens_shading_correction.grid_width` / `grid_height` into the output YAML.

Gains are clamped to [1.0, 15.99] to stay within boltISP's Q5.11 range.
The `k1`/`k2` keys are removed from the output (boltISP ignores them anyway).

## CCM normalization (brilliantISP fix — applied)

**Bug fixed:** `color_correction_matrix.py` previously normalised the CCM input
by `2^output_bit_depth − 1 = 255` instead of `2^pipeline_rgb_bit_depth − 1 = 65535`.
This saturated all pixels above 255 to 1.0 when CCM was enabled.

The fix uses `sensor_info.pipeline_rgb_bit_depth` (default 16) for both the
normalise and scale-back steps.  CCM is now safe to enable in `AD_cam.yml`.

## Colour saturation

| ISP | Method | Stage |
|-----|--------|-------|
| **boltISP** | Luma-preserving blend: `c′ = L + (c − L) × S` where `L` = BT.709 luma | CCM stage (linear, pre-tone-map) |
| **brilliantISP (updated)** | Same luma-preserving blend: `c′ = L + (c − L) × S` (BT.709 luma) | CSC stage (linear 8-bit, post-tone-map) |

Both ISPs now use the **same saturation formula**.  The remaining difference is
the pipeline position: boltISP applies saturation before tone mapping; brilliantISP
applies it after.  For most images this produces a visually similar result.

## LDCI placement

| ISP | Placement | Domain |
|-----|-----------|--------|
| **boltISP** | After all tiles, post-gamma | 8-bit gamma-encoded RGB |
| **brilliantISP (`ldci.post_gamma: false`, default old)** | YUV chain before gamma | 8-bit linear YUV |
| **brilliantISP (`ldci.post_gamma: true`, recommended)** | After gamma on 8-bit RGB | 8-bit gamma-encoded RGB |

Set `ldci.post_gamma: true` in the shared config to match boltISP:

```yaml
ldci:
  is_enable: false     # or true
  post_gamma: true     # run after gamma on 8-bit RGB (boltISP-compatible)
  clip_limit: 2.0
  wind: 128
```

## Auto Exposure luma weighting

Both ISPs now use **BT.709** luma weights `[0.2126, 0.7152, 0.0722]` for AE
metering (brilliantISP `auto_exposure.py` updated from Rec. 601).

---

## AWB PCA gain floor

Both ISPs floor R and B gains to a minimum of **1.0** after PCA:
- brilliantISP: explicit `rgain = max(rgain, 1)` in `auto_white_balance.py`
- boltISP: `min_gain = 1.0f` in `clampFloat` applied to PCA and GreyWorld gains

No change needed for boltISP; this is already aligned.

## Remaining known-unharmonised differences

The following differences are structural and not practical to resolve without
major refactoring.  They produce ≤ low-medium visual impact.

| Difference | brilliantISP | boltISP | Impact |
|------------|-------------|---------|--------|
| **Tiling** | Full-frame processing | 256×32 tiles, overlap 2 | Sub-pixel seam artefacts near tile edges for some filters |
| **DPC algorithm** | 5×5 cross-neighborhood min/max, interpolated replacement | 8-neighbor median replacement | Different defect sensitivity and fill value |
| **BNR algorithm** | Joint bilateral (Python float) | Per-channel bilateral (fixed-point LUT) | Structurally similar; tune sigma params to match RMS |
| **Fixed-point truncation** | float32 throughout | `>> 10 / >> 11 / >> 14` truncation | ±1 LSB differences; unavoidable without refactoring boltISP |
| **Saturation position** | Post-tone-mapping (CSC stage) | Pre-tone-mapping (CCM stage) | Low for typical saturation values near 1 |
| **Sharpen domain** | Y-channel of linear YUV | BT.709 luma of linear Q26.10 RGB | Functionally similar; same sigma/strength produce comparable edges |

## Export script usage

`tools/export_boltisp_yaml.py` converts a brilliantISP YAML into a
boltISP-compatible file, handling:

- Inline list formatting for arrays
- Tone-mapping operator translation (`tone_mapper` → `operator`)
- Hable parameter mapping to `hdr_tone_mapping.*`
- LSC radial-polynomial → grid-table conversion

```bash
python tools/export_boltisp_yaml.py \
    --input  config/AD_cam.yml \
    --output /path/to/boltISP/config/AD_cam_from_brilliant.yml \
    [--lsc-grid-width  17] \
    [--lsc-grid-height 17]
```

Re-run this script whenever `config/AD_cam.yml` is modified to keep the boltISP
config in sync.
